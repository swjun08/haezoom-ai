# 검증 기록 · 2026-11-06

## 통과

2.3: 실제 PDF 파일을 생성하고 파일 URL 액세스가 허용된 별도 Chromium의 내장 PDF 화면에서 content script가 로드되어 원형 로고와 메뉴를 표시하는 것을 검증했습니다(`tests/pdf.mjs`). 일반 페이지에서 버튼을 중앙·왼쪽 아래·오른쪽 위로 드래그한 후 메뉴가 로고와 겹치지 않고 화면 안에 표시되는지 좌표로 검사합니다. 사용자의 실제 Chrome에서도 2.2 업데이트 후 로고의 드래그 위치 변경을 확인했습니다. 사용자의 Chrome에 로컬 PDF 접근 권한을 새로 적용하는 작업은 별도 확인 대상입니다.

2.2 추가 브라우저 검증: 실제 포인터 드래그로 버튼 이동, 이동 후 메뉴가 열리지 않음, 위·왼쪽 경계 제한, 작은 화면으로 리사이즈한 뒤 위치 유지, 이동한 위치에서 메뉴가 뷰포트 안에 표시됨. 캡쳐 UI는 모의 runtime + 테스트 페이지 스크린샷으로 영역 500×250 선택 → 미리보기 → 가져오기 결과의 실제 이미지 픽셀 크기, 가져오기 전 결과 전달 없음, Esc 취소를 검증했습니다. **Chrome captureVisibleTab 자체 권한 흐름과 실제 OCR은 이 테스트에서 검증하지 않았습니다.**

- `npm test`: 8개 테스트. 달력 날짜 유효성, 가상 문서 5종, 잘못된 응답 거부, 준비물·비용·제출처·근거·출처 보존.
- `npm run check`: manifest 진입점, HTML 자산 존재, UI 버전의 미사용 Calendar/알림 권한 제거 확인.
- Playwright의 별도 Chromium 임시 프로필에서 실제 압축해제된 확장을 로드.
- 샘플 결과 → 목록 → 날짜 편집 → 사용자 확인 → 완료 → 필터 → 새로고침 초기화.
- 실제 확장 runtime/background를 통한 선택 문장 임시 전달과 탭 열기, 읽은 후 세션 전달값 삭제.
- 1440px/390px 화면 캡처, 좁은 화면 가로 넘침 없음, workspace 페이지 자바스크립트 오류 없음.
- 드래그 도우미 DOM 테스트: 가상 HTTPS 공지에서 텍스트 선택 시 표시, 클릭 전 runtime 메시지 없음, 클릭 시 선택 내용 전달, 입력창 제외. **이 테스트의 페이지 runtime은 모의 객체**이며 Chrome 사이트 권한 승인/등록의 종단 검증은 아니다.
- 문서 결과 화면과 선택 도우미 스크린샷을 직접 시각 검토.

## 미검증 / 인계 후 필요

2.1 추가 검증: 별도 브라우저의 도우미 DOM 테스트에서 상시 표시되는 원형 버튼, 기능 메뉴 열기, 내 할 일 이동 메시지, Esc 닫기, 페이지에서 숨기기를 확인했습니다. 이 테스트의 runtime은 모의 객체이며 사이트 권한 승인 흐름은 별도입니다. 메뉴 스크린샷은 `06-floating-menu.png`입니다.

- 사용자의 실제 Chrome 프로필에는 설치하거나 변경하지 않음.
- 실제 사이트의 권한 승인 팝업, 도우미 등록·해제·재시작, SPA/iframe/브라우저 PDF 뷰어는 수동 확인 필요.
- PDF.js/Tesseract 파일 존재와 참조는 확인했으나 실제 PDF·이미지/스캔 OCR 정확도·표 구조·외부 언어 데이터 다운로드는 이번 UI 테스트 범위 밖.
- 실제 AI 요청, 서버 배포, 영구 저장, 알림, Google OAuth/Calendar는 이번 구현 범위 밖.
- 샘플은 수작업 기대 결과. 실제 AI 정확도나 성공률의 근거로 사용할 수 없음.
- macOS 네이티브 보조기기/스크린리더로 전체 사용성을 검증하지 않음.

## 재현

Node 22+, Playwright 1.62.1과 해당 Chromium을 설치하고 `npm test`, `npm run check`, `npm run test:browser` 실행. 마지막 명령은 별도 임시 브라우저 프로필과 `docs/screenshots/`를 만든다. 시스템 정책으로 브라우저 실행이 차단되면 실행 권한을 부여한 환경에서 재시도한다.
