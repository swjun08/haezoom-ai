## 이번에 제가 구현한 범위

이번 작업은 사용자가 보는 화면과 문서를 가져오는 경험 개선입니다. 기존 CRX는 참고 자료로 두고 새 확장 프로그램을 구성했습니다. 기존의 실제 AI 서버 호출·저장·알림·Calendar 코드를 새 화면에 연결하는 작업은 남겨뒀습니다.

| 수정한 부분 | 바꾼 이유 |
|---|---|
| 이편한자막·말랑과 맞춘 Pretendard, 흰색/회색 바탕, 검정 버튼, 둥근 카드 | 팀 서비스의 일관성을 유지하고 화면을 간결하게 만들기 위해 |
| 페이지 위 동그란 h. 버튼과 펼쳐지는 메뉴 | 확장 아이콘을 매번 찾지 않고 기능을 열 수 있도록 |
| 버튼 드래그 이동, 화면 밖 이동 제한, Alt+방향키 이동 | 본문이나 사이트 버튼을 가리지 않도록 |
| 이동한 버튼의 위/아래 여유 공간에 맞춰 열리는 메뉴 | 로고와 메뉴가 겹치던 문제 해결. 공간 부족 시 메뉴 내부 스크롤 |
| 메뉴 소개를 ‘공지 속 할 일과 마감일을 한눈에 정리해요.’ 한 줄로 축소 | 중복 홍보 문구와 개발 상태 설명을 줄이고 기능에 집중하도록 |
| PDF 업로드와 화면 캡쳐 버튼 분리 | 파일을 가져올 때와 현재 화면을 가져올 때의 선택을 명확하게 하기 위해 |
| 화면 영역 선택 → 미리보기 → 확인 후 가져오기 | 필요 없는 정보나 개인정보까지 실수로 가져오지 않도록 |
| 문장 드래그 옆 정리 버튼, 선택 글자 수·메뉴 안 미리보기, Esc 닫기·입력창 제외 | 선택 범위를 확인하고 작성 중인 글에 방해받지 않도록 |
| 한 번 승인하면 HTTP/HTTPS 사이트에 자동 표시하는 전체 사이트 모드 | 사이트마다 도우미를 다시 켜야 하는 번거로움 해소 |
| 로컬 PDF 화면 로고 지원 및 파일 접근 설정 안내 | 가정통신문을 브라우저 PDF 뷰어로 볼 때도 동일한 진입점을 제공하도록 |
| 원문 근거·준비물·비용·제출처·미확정 날짜를 유지하는 결과 카드 | 요약만 보고 판단하지 않고 사용자가 내용을 확인하도록 |
| 샘플 5종, 날짜/내용 편집·완료·검색·필터·삭제·JSON 내보내기 화면 | 서버 연결 전에 사용자 흐름을 검토할 수 있도록 |

## 현재 상태를 꼭 구분해 주세요

- 샘플 버튼은 수작업으로 작성한 예시 결과입니다. 실제 AI 분석이나 정확도 검증 결과가 아닙니다.
- 목록의 수정·완료·삭제는 현재 화면 메모리에서 동작합니다. 새로고침하면 초기화됩니다. 영구 저장은 미연결입니다.
- 선택 텍스트와 캡쳐 이미지는 화면 간 전달을 위해 브라우저 세션에 임시 보관하고 읽은 뒤 삭제합니다. 드래그·캡쳐만으로 AI에 전송하지 않습니다.
- 이미지/PDF 텍스트 추출 코드와 입력 화면은 있습니다. 실제 한국어 OCR 정확도·복잡한 표·대용량 문서는 추가 검증해야 합니다.
- 전체 사이트 자동 표시는 최초 웹사이트 접근 권한 승인이 필요합니다. 크롬 설정·웹스토어 등 제한 화면까지 지원한다는 의미는 아닙니다.
- 로컬 PDF 로고는 Chrome의 ‘파일 URL에 대한 액세스 허용’이 필요합니다. PDF 내부 텍스트 선택을 직접 읽는 기능은 미구현이며 캡쳐/업로드 경로를 사용합니다.
- 화면 캡쳐 권한이 부족하면 상단 해줌 아이콘의 ‘현재 화면 캡쳐하기’로 시작해야 합니다.

## 팀원이 이어서 해주실 일

1. 새 문서 정리 화면의 `run` 버튼에 실제 분석 API를 연결해 주세요. 사용할 제공자·모델과 변경 이유를 팀에 공유해 주세요.
2. `summary / tasks / schedules` 응답을 `core.mjs`의 검증/변환 함수와 연결하고, 준비물·비용·제출처·근거·검토 필요 상태를 유지해 주세요.
3. 연도/발행일이 불명확한 날짜를 임의로 확정하지 말고 사용자 확인 대상으로 남겨 주세요.
4. 샘플 문서 5개 이상에 대해 원문·기대값·실제 JSON·누락/오류를 기록해 주세요. 현재 고정 샘플을 AI 성공 사례로 사용하지 말아 주세요.
5. API 키는 서버에서 관리하고 인증·사용량 제한·오류 응답·타임아웃을 적용해 주세요. 실제 외부 전송 전 동의/안내도 연결해 주세요.

### 확장 프로그램 담당

1. 메모리 목록을 실제 저장소에 연결해 주세요. 안정적인 항목 ID와 원문/상세 필드/사용자 확인 상태를 보존해 주세요.
2. 선택 텍스트·PDF·캡쳐 입력이 모두 같은 저장 모델로 이어지도록 연결해 주세요.
3. 사용자 확인 완료·유효한 날짜·미완료 항목만 Calendar/알림 대상으로 처리해 주세요. 모든 진입점에서 같은 조건을 사용해야 합니다.
4. Google OAuth 설정과 일정 등록·수정·재시도·중복 방지 정책을 구현해 주세요. 로컬 항목 삭제/완료와 외부 일정의 관계도 안내해 주세요.
5. 한국 시간 기준 마감 3일 전·1일 전·당일 알림과 재시작 복구를 구현해 주세요.
6. 실제 Chrome에서 전체 사이트 권한 승인·해제, PDF 파일 접근, 재시작, 캡쳐 권한 부족·취소·재시도, OCR 실패를 검증해 주세요.

### PM 및 팀 공통

- JSON 필드와 확인 상태의 의미를 먼저 확정하고 연동해 주세요.
- 화면 디자인을 다시 만드는 것보다 연결 누락·오류 복구·데이터 보존을 먼저 확인해 주세요.
- 이 순서로 데모가 이어지면 완료로 보겠습니다: 문서 가져오기 → 실제 AI 분석 → 원문/날짜 확인 → 저장 → 탭 재열기 → 정보 유지 → 알림/Calendar 한 번만 등록.
- 작업 공유 시 수정한 소스, 테스트 결과, 남은 문제를 함께 전달해 주세요. 일정은 기존 팀 일정과 다시 대조해 확정하겠습니다.

## 개발 시작

`chrome://extensions` → 개발자 모드 → 압축해제된 확장 프로그램 로드 → 저장소의 `extension` 폴더 선택. 일반 사이트는 해줌 팝업에서 전체 사이트 모드를 한 번 승인합니다. 로컬 PDF는 상세 설정의 파일 URL 액세스도 켜 주세요.
